# 2051년 첨부 백업의 자동 저장 용량 오류

확인일 2026-11-07. 사용자가 제공한 우익수 백업을 읽어 재현했다. 원본 JSON은 수정하지 않았고 저장소에 복사하지 않았다. 원본 SHA-256은 `688664392de5c83a0a58acb13672ca2bd271f3d2ad669babc96071f8ddedb465`로 전후 일치했다.

## 재현한 원인

파일은 2051년·42세·은퇴 상태이며, 고교부터 포함한 시즌 행 24개가 있다. 파일 자체가 이미 `packed-stats-v1`이다. 그 방식으로 다시 저장해도 **5,202,466자**였다. 예전 투타 기록 배열 압축만으로는 시즌마다 쌓이는 리그 선수·운영 기록을 충분히 줄이지 못했다.

독립 Chrome 컨텍스트에서 원본 로드 → 현재 커리어 자동 저장 → 은퇴 보관을 순서대로 실행했다. 현재 저장은 성공했지만 뒤이어 **42,617자**의 은퇴 보관 목록을 쓰면서 실제 `QuotaExceededError`가 발생했다. 기존 `persist()`는 이 두 저장을 하나의 try/catch로 묶어, 현재 선수가 이미 저장됐어도 전체가 자동 저장 실패인 것처럼 알렸다. 첨부 JSON 자체에는 당시 브라우저의 다른 키·예외 로그가 없으므로 사용자의 모든 과거 실패가 같은 경로였다고 단정하지는 않는다. 이번 실패 경로는 제공된 데이터만으로 실제 브라우저에서 재현됐다.

[MDN의 저장 할당량 설명](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)은 출처별 Web Storage 한도와 초과 예외를 설명한다. 여기서의 문자 수는 시험한 Chrome의 저장 문자열 기준이며, UTF-8 JSON 파일 바이트 수와 같지 않다. 원본 파일은 5,436,165바이트다.

## 수정

- 기존 투타 배열 압축 위에 **무손실 DEFLATE 압축**을 추가했다. 문자열·정밀 숫자·모든 시즌과 리그 데이터를 그대로 복구한다. 기록을 자르거나 과거 리그·2군 기록을 삭제하지 않는다.
- `src/storage-codec.js`는 고정 버전 **fflate 0.8.2**의 zlib 압축과 UTF-8 변환을 쓴다. 압축 바이트는 제어문자·서로게이트가 없는 15비트 문자로 포장한다. 압축 형식, 원래 길이, 압축 길이와 체크섬을 함께 저장해 누락·손상을 확인한다. 지원하지 않는 압축과 잘못된 길이·체크섬은 로드 오류로 처리한다.
- [공식 fflate 소스/버전](https://github.com/101arrowz/fflate/tree/v0.8.2)과 [npm 고정 배포물](https://registry.npmjs.org/fflate/-/fflate-0.8.2.tgz)을 사용했다. `src/vendor/fflate.js`, MIT 라이선스, 출처 문서를 함께 보관한다. 실행 시 CDN 접속이나 패키지 설치는 필요 없다.
- 현재 커리어와 은퇴 목록 **모두** 새 압축을 사용한다. 작은 저장은 기존 JSON으로 두되, 실제 용량 초과 시 압축을 재시도한다. 그래도 부족하면 게임이 소유한 구 저장·백업만 무손실 압축하고 다시 쓴다. 읽을 수 없는 키·다른 서비스 키는 건드리지 않고, 기존 저장을 먼저 삭제하지 않는다. 각 `setItem`이 실패하면 해당 키의 이전 값은 남는다.
- 버전 1~7의 일반 JSON과 기존 `packed-stats-v1`도 계속 읽는다. 압축 자동 저장의 직접 백업도 불러올 수 있다. 저장 목록의 선수명·연도는 미리보기 메타데이터로 표시한다. **일반 내보내기는 종전처럼 전체 JSON**이며 새 압축 형식으로 바꾸지 않았다.
- 현재 저장과 은퇴 보관의 실패를 구분한다. 은퇴 보관만 실패한 경우 현재 선수는 저장됐음을 명확히 표시한다.
- 이전 `archiveEntries()`는 해독 실패를 빈 목록으로 돌려줘 후속 저장이 원본을 덮어쓸 수 있었다. 이제 읽기 실패 시 쓰기·교체·병합을 막고 원본을 보존한다. UI는 읽기 실패를 알리고 **보관 원본 내보내기**를 제공한다. 손상 자체를 추정해 복구하지는 않는다.

## 실제 백업 결과

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 현재 자동 저장 | 5,202,466자 | **596,107자** |
| 동일 선수 은퇴 보관 1명 | 42,617자 | **4,836자** |
| 현재 저장 감소율 | — | **88.5%** |
| 현재 저장 + 은퇴 보관 실행 | 은퇴 보관에서 QuotaExceededError | 성공 |

동일 분량의 별도 선수 복사본을 7명 보관한 경우 은퇴 목록은 29,215자, 현재 저장과 키 이름까지 합한 총 길이는 **625,373자**였다. 실제 제공된 7명의 서로 다른 저장을 검증했다는 의미는 아니다. 현재 저장 1회의 Node 측정은 약 311ms였으며, 하드웨어·시즌 수에 따라 달라진다.

변경 후 저장 → 복구한 전체 커리어를 원본 로드 결과와 JSON으로 표현 가능한 모든 필드에 대해 비교해 일치했다. 개인/팀/리그 기록, 계약·거래·급여 이력, 마지막 리그, 통산 WAR 및 은퇴 보관 WAR가 유지됐다. 같은 은퇴 선수를 여러 번 저장해도 중복되지 않았다.

## 검증

- 전체 `node --test tests/*.test.js`: **218개 통과, 0개 실패**.
- 새 회귀: 유니코드·한글·이모지·고립 서로게이트·제어문자·소수점 무손실 복구, 기존 JSON 호환, 체크섬·길이·미지원 형식 거부, 용량 제한에서 구 키 압축과 이전 데이터 보존, 24시즌 현재 저장·은퇴 7명·교체·내보내기·복원·WAR 일치, 손상 목록 덮어쓰기 방지.
- 독립 Chrome **390px·1280px**에서 실제 첨부 파일로 다음을 확인했다: 기존 자동 저장의 재로딩 시 이관, 파일 불러오기, 저장 오류 없음, 은퇴 목록 생성, 새로고침 뒤 중복 없음, 기록 펼치기, 일반 JSON 다운로드 후 전체 시즌·급여·거래·WAR 일치, 가로 넘침 없음.
- 별도 손상 은퇴 목록을 넣었을 때 현재 선수 저장은 유지되고 손상 원문은 바뀌지 않았으며, 복구용 원본 다운로드가 원래 문자열과 일치했다. 실제 사용자 브라우저 저장은 조작하지 않았다.

주요 파일은 `src/storage-codec.js`, `src/engine.js`, `src/storage-management.js`, `src/app.js`, `tests/storage-codec.test.js`, `tests/storage-management.test.js`다. 모듈·화면 캐시는 7.28로 갱신했다.

## 남는 한계

Web Storage 용량을 무한하게 늘린 것은 아니다. 같은 출처의 다른 데이터가 가득 차 있거나 저장 권한이 차단되면 압축 후에도 실패할 수 있다. 이때 기존 기록을 자동 삭제하지 않고 실패와 내보내기를 안내한다. 손상된 압축 데이터는 체크섬으로 탐지할 뿐 원문 없이 복원하지 않는다. 새 압축 자동 저장은 새 코드에서 읽어야 하며, 이전 코드로 이동할 때는 일반 JSON 내보내기를 사용해야 한다. Safari·Firefox·실제 모바일 기기의 용량 정책은 이번에 직접 검증하지 않았다.
