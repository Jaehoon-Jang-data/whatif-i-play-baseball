# 포스트시즌 확인 중단과 자동 저장 크기 수정

사용자가 내보낸 2040년·2042년 파일을 현재 저장 로직으로 불러와 상태를 추적했다. 2040년 파일에는 확인 대기 중인 `postseason` 이벤트가 있었다. 2042년 파일은 한국시리즈 우승 기록과 선수 우승 반지가 남아 있지만 `pendingEvent`가 비어 있었다. 이는 우승 확인이 상태에서 먼저 처리된 뒤, 결과 화면 렌더링이 중단된 상황과 일치한다.

실제 화면에서 결과 지표를 만드는 `metrics()`가 `careerRecordMarker()`를 호출했지만 `src/app.js`의 엔진 가져오기 목록에는 해당 함수가 없었다. 따라서 이벤트를 확인해 `pendingEvent`를 비운 직후 결과 화면에서 `ReferenceError`가 났다. 기존 우승 팝업 DOM은 남아 다음 클릭 때 `확인할 이벤트가 없습니다`가 표시됐다. 누락된 가져오기를 추가하고, 이벤트 확인 후 화면 그리기가 실패하면 대기 이벤트와 대기열을 되돌리도록 했다.

두 내보내기 파일에는 브라우저의 저장소 사용량과 저장 예외 종류가 없으므로 당시 **자동 저장 실패의 정확한 예외는 확인할 수 없다**. 다만 저장 문자열이 2040년 3,463,654자, 2042년 3,883,054자에 달해 브라우저 저장 용량에 가까워지는 문제가 확인됐다. 시즌마다 반복되는 투타 기록 객체를 배열로 압축하고, 최종 시즌 리그 기록과 내용이 같은 `latest` 복사본은 저장 시 생략한다. 불러올 때 원래 객체와 `latest`를 복원한다. 내보내기 JSON 형식은 그대로 유지하고 기존 비압축 버전 1~7 파일도 읽는다.

| 제공된 파일 | 이전 저장 문자열 | 새 저장 문자열 | 감소율 |
|---|---:|---:|---:|
| 2040년 | 3,463,654자 | 2,629,920자 | 24.1% |
| 2042년 | 3,883,054자 | 2,953,712자 | 23.9% |

두 파일 모두 새 형식으로 저장·복구한 뒤 연도, 시즌 수, 거래 이력 수, 포스트시즌 반지 수, 이벤트 상태가 일치했다. 2040년 이벤트를 확인하고 다시 저장·복구해 이벤트가 재등장하지 않음을 확인했다. 별도 로컬 브라우저에서도 2040년 원본 파일의 포스트시즌 팝업 확인 → 결과 화면 → 새로고침을 통과했다. 2042년 원본 파일은 결과 화면을 연 뒤 `다음`으로 2043년 스토브리그에 진입했다. 전체 `node --test tests/*.test.js`는 139개 통과했다.

남는 한계: 브라우저의 같은 출처에 다른 대용량 저장 데이터가 많이 있으면 새 압축 형식도 할당량을 넘을 수 있다. 이때는 저장 공간 부족을 별도 문구로 표시하고 JSON 내보내기를 안내한다. 제공 파일의 거래 이력에는 2041년 시즌 중 트레이드와 2차 드래프트 이동이 모두 보존되어 있었으며, 이 이동들이 화면 예외의 직접 원인은 아니었다.
