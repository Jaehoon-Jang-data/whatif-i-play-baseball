## 최종 기준

모두 **프로 1군 정규시즌** 기준이다. 고교·대학·2군·상무·현역 복무·국제대회·포스트시즌 기록은 제외한다. 투타 전환 경력은 해당 역할의 기록끼리 합산한다.

| 구분 | 항목 | 통산 첫 달성 기준 |
| --- | --- | --- |
| 타자 | 안타 | 1,000 / 1,500 / 2,000 / 2,500 |
| 타자 | 홈런 | 100 / 200 / 300 / 400 / 500 |
| 타자 | 타점·득점 각각 | 500 / 1,000 / 1,500 |
| 타자 | 도루 | 100 / 200 / 300 |
| 타자 | 출장 | 1,000 / 1,500 / 2,000 / 2,500경기 |
| 투수 | 탈삼진 | 1,000 / 1,500 / 2,000 / 2,200 / 2,300 |
| 투수 | 승리 | 100 / 150 / 200승 |
| 투수 | 이닝 | 1,000 / 1,500 / 2,000 / 2,500 |
| 투수 | 세이브·홀드 각각 | 100 / 150 / 200 |
| 투수 | 등판 | 500 / 700 / 1,000경기 |

| 구분 | 시즌 기준 |
| --- | --- |
| 타자 | 20홈런-20도루 / 30홈런-30도루 / 40홈런-40도루 중 **그 시즌 최상위 하나만** |
| 타자 | 200안타 / 100타점 / 100득점 / 100타점-100득점 |
| 투수 | 200탈삼진 / 20승 / 200이닝 / 40세이브 / 30홀드 |

100타점·100득점·복합 배지는 서로 다른 세 개다. 복합 배지는 같은 시즌에 두 조건을 모두 충족해야 한다. 시즌 기록은 다음 시즌에도 다시 충족하면 그 시즌 배지를 다시 표시한다. 통산 기록은 `시작 전 누적 < 기준 ≤ 종료 누적`인 첫 시즌에만 표시한다. 한 시즌에 통산 기준을 여러 개 통과하면 모두 표시한다.

## 데이터 흐름과 구현

- `src/record-achievements.js`: 순수 판정 함수와 기준표. `history`에서 해당 연도 이전의 같은 역할 `stat`을 합산하고 해당 시즌 `stat`과 비교한다. 배열 정렬 순서나 객체 동일성에 의존하지 않는다. 이닝은 `outs` 정수로 판정한다. `teamSegments`는 이미 `stat`에 포함된 이적 전후 합계이므로 재합산하지 않는다.
- `src/presentation.js`: 타이틀과 같은 `award-badge` 구조에 별도 `record-badge` 클래스·영역을 사용한다. `src/app.js`에서 결과의 1군 탭에만, 타이틀 바로 다음에 배치한다. `style.css`에서 하늘색을 지정하며 기존 크기·패딩·모바일 줄바꿈을 공유한다. 짧은 `1군 정규시즌` 안내로 집계 범위를 표시한다.
- **저장 변경 없음:** 배지를 `awards`, 수상 이벤트, 연봉·옵션·계약 기록에 넣지 않는다. 과거 시즌·불러온 저장·은퇴 보관의 원기록으로 재계산한다. 시즌 성적 수정 시 다음 표시에서 즉시 반영된다. 달성 여부 캐시가 없어 저장 용량을 늘리지 않는다.
- 과거 시즌의 특정 원기록이 누락됐으면 그 항목의 통산 돌파 시점은 추정하지 않는다. 군 복무·무출장 시즌은 누적을 늘리지 않는다. 외부에서 이력을 삭제한 파일의 사라진 시즌은 복원할 수 없다.
- **미구현 희귀 경기 기록:** 정상 저장에는 완투·완봉 횟수, 경기별 무안타·출루 허용·실책과 퍼펙트게임 판정 자료가 없다. 시즌 합계 27아웃·0피안타 등으로 특정 경기 결과를 추정하지 않는다. 개발용 선택적 투구 로그는 모든 저장에 존재하지 않아 근거로 삼지 않았다.
- `index.html`과 모듈 참조 캐시 버전은 7.30이다. 수상·경기·성장·계약 산식은 변경하지 않았다.
