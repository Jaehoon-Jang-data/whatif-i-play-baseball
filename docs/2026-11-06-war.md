# 2026-11-06 시즌 WAR

## 범위와 참고 자료

화면 명칭은 `WAR`, 설명은 `시뮬레이션 WAR`다. 기관별 WAR를 그대로 복제하거나 공식 KBO WAR라고 주장하지 않는다. 수상·성장·급여 산식에는 사용하지 않고 기록 표시와 은퇴 시즌 비교에만 추가했다.

2026-11-06 확인 자료:

- [FanGraphs 타자 WAR](https://library.fangraphs.com/war/war-position-players/): 타격·주루·수비·포지션·리그·대체 수준을 득점으로 합산하고 득점/승으로 환산하는 구조, 포지션 조정과 시즌별 득점/승, 리그 전체 대체 수준 배분을 참고했다.
- [MLB WAR 개요](https://www.mlb.com/glossary/advanced-stats/wins-above-replacement): 대체 선수 대비 가치라는 개념을 참고했다.
- 요청된 [Baseball-Reference 타자 설명](https://www.baseball-reference.com/about/war_explained_position.shtml), [투수 설명](https://www.baseball-reference.com/about/war_explained_pitch.shtml)은 직접 열었으나 HTTP 403으로 본문을 확인하지 못했다. 세부 공식을 확인했다고 주장하지 않으며 bWAR 일치 검증도 하지 않았다.

## 저장 흐름과 입력

기존 시즌 행의 `stat`, `role`, `position`, `team`, `teamSegments`, `league.players`, `league.teams`를 사용한다. 1군과 2군은 각각 `league`와 `minorLeague`로 분리하고 포스트시즌·대표팀·복무 기록은 프로 정규시즌 WAR 통산과 TOP 3에서 제외한다.

새 시즌에는 선수별 `warUsage`를 추가한다.

- 타자: 실제 시뮬레이션 수비 라인업에 있던 포지션별 아웃 수(지명타자는 해당 시간의 출장 비중), 실제 타석별 구장 계수 합계, 팀별 타석 수.
- 투수: 실제 선발/구원 아웃 수, 각 아웃의 구장 계수 합계, 팀별 아웃 수.
- 이 기록은 RNG를 소비하지 않는다. 기록·경기 결과·부상·선발 판단을 바꾸지 않는다.

기존 저장의 타격 결과는 단타=`H-2B-3B-HR`, 2·3루타, 홈런, 볼넷, 사구, 타석, 도루 성공·실패를 사용한다. 투수는 아웃, 선발·등판, 피홈런·볼넷·삼진을 사용하고, 실점·자책점 기반 RA9/ERA도 진단값으로 제공한다. 능력치·현재 소속·현재 포지션을 과거 시즌 기록에 덮어쓰지 않는다.

추가 진루·병살 회피·도루 저지·포수 프레이밍·타구 추적·실제 수비 득점 지표는 없다. 투수의 피사구·고의사구도 별도 저장하지 않는다. 실책이나 수비 능력치만으로 정밀 수비 득점을 만들지 않고 **수비 득점은 0**으로 둔다. 따라서 같은 포지션에서 수비 능력치만 높은 선수의 WAR가 자동으로 높아지지는 않는다.

## 계산 모델 v1

다음 상수는 게임 추정치다. 고정된 타격 가중치는 매년 실측한 선형 득점표가 아니다. 음수 WAR도 유지하고 규정타석·이닝 미달 선수를 강제로 0이나 계산 불가로 만들지 않는다.

### 공통 환경과 대체 수준

`IP = 리그 전체 투수 아웃 / 3`, `RA9 = 리그 팀 득점 합 × 9 / IP`, `득점/승 = RA9 × 1.5 + 3`.

해당 시즌 관측 득점·이닝을 사용하므로 `environment` 배수의 영향도 실제 결과를 통해 반영된다. 별도의 현대 리그 득점 평균은 넣지 않는다.

리그 전체 대체 수준 풀은 `실제 리그 경기 수 × 1000/2430 WAR`, 타자 57%·투수 43%로 배분한다. MLB에서 쓰이는 배분 규모를 참고한 게임 선택이며 KBO 실측 대체 수준은 아니다. 10팀·144경기는 총 296.30 WAR다. 이를 타자는 타석, 투수는 선발 아웃 + 구원 아웃 × 0.7에 비례해 대체 득점으로 배분한다. 구 기록의 실제 선발/구원 이닝이 없을 때만 `GS/G`로 이닝 비중을 근사한다. 레버리지 가산이나 세이브 가산은 없다.

### 타자

1. 상대 득점값 `L = .47×1B + .78×2B + 1.09×3B + 1.40×HR + .33×BB + .35×HBP − .27×(PA−H−BB−HBP)`.
2. 타격 득점 = `L − 리그 L/PA × 선수 PA`. 아웃이 있는 타석은 음의 가치를 가진다. SF도 아웃 타석에 포함한다. 삼진을 다른 아웃과 별도로 중복 감점하지 않는다.
3. 주루 득점 = `.2×SB − 도루실패비용×CS − 리그 기회당 주루 득점×(1B+BB+HBP)`. 실패비용은 `2×리그 득점/아웃 + .075`. 추가 진루는 미반영한다.
4. 수비 득점은 중립 0. 포지션 득점은 162경기·9이닝 기준 포수 +12.5, 유격수 +7.5, 2루수·3루수·중견수 +2.5, 좌·우익수 −7.5, 1루수 −12.5, DH −17.5를 실제 포지션별 아웃 비중에 곱한다. KBO 포지션 가치의 별도 추정은 아니다.
5. 리그 조정은 리그 포지션 득점을 PA 비율로 빼서 평균 이상 기여 합이 중립이 되게 한다. 타격·주루는 앞 단계에서 이미 평균 대비로 중심화한다.
6. 구장 조정은 `−(개인 구장 노출계수−리그 타석 가중 계수) × 리그 R/PA × PA`.
7. 위 득점과 PA 비례 대체 득점을 합해 그 시즌 득점/승으로 나눈다.

### 투수

**실제 실점 기반 bWAR가 아닌 FIP 계열 기록 기반**이다. `(13×HR + 3×BB − 2×K) / IP + C`를 사용하고 `C`는 리그 이닝 가중 평균이 해당 시즌 RA9가 되도록 맞춘다. ERA에 맞추는 표준 FIP와도 다르며 수비 독립 성분을 게임 실점 환경에 놓기 위한 선택이다. 피사구 미기록은 0으로 처리한다.

투구 득점 = `(리그 RA9 − 개인 FIP 계열 값) × IP/9`. 투구 구장 조정 = `(개인 구장 노출계수−리그 이닝 가중 계수) × 리그 RA9 × IP/9`. 선발/구원 실제 이닝 비중에 따른 대체 득점을 더하고 득점/승으로 나눈다. 피안타·실점·자책점은 이 모델의 주 가치에 직접 혼합하지 않으며 RA9/ERA 진단과 한계 검토에 쓴다. 승·패·세이브·홀드는 직접 가치 입력이 아니다. 같은 시즌 한 역할의 타자/투수 WAR를 더하는 경로는 없다.

### 구장·구 기록의 한계

구장 계수는 실제 KBO 구장 실측값이 아니라 기존 게임이 안타·홈런 확률에 쓰는 `team.park`다. 이를 득점 환경의 선형 보정값으로 사용하는 것은 근사다. 새 시즌은 홈구장 절반을 다시 곱하지 않고 실제 타석·아웃별 계수를 사용한다.

리그는 있으나 출장 노출 기록이 없는 구 시즌은 `min(G, PA/4.3)`을 한 포지션의 경기 상당량으로, 구장은 홈 절반·중립 원정 절반으로 추정한다. 시즌 중 이적 구 기록은 보존된 팀별 타석/이닝 비중을 사용한다. 화면에 ‘일부 기록 추정’을 표시한다. 사구·도루 실패가 원천 기록에서 빠진 리그는 누락 경고를 진단에 남긴다. 이미 옛 이관에서 0으로 채워진 기록은 진짜 0과 구별할 수 없다.

## 계산 시점·은퇴 보존·화면

`seasonWAR(row)`는 조회할 때 원기록과 해당 시즌 리그 요약에서 다시 계산한다. 캐시된 최종 WAR 숫자를 신뢰하지 않으므로 시즌 기록이 바뀌어도 이전 값이 남지 않는다. `components`, `diagnostics`, `runs`, `runsPerWin`, `method`, `notes`를 개발용 반환값으로 제공한다. `teamWarReport(league)`는 팀별 합계와 실제/모형 승수 편차를 반환한다. 시즌 중 이적 선수는 실제 팀별 타석/아웃 비율로 시즌 WAR를 배분한다. 팀별 타격 결과를 각각 다시 평가한 정확한 구간 WAR는 아니다.

은퇴 `archiveEntry`는 전체 리그 명단 대신 시즌별 `warContext`(합산 환경·상수·구장)와 본인의 `warUsage`, 팀별 이동 기록을 보존한다. 같은 버전의 계산을 전체 커리어·압축 저장·복구·은퇴 보관에서 동일하게 적용한다. 나중에 모델을 바꾸면 버전별 처리도 함께 설계해야 하며 v1 문맥을 다른 버전으로 조용히 계산하지 않는다.

기존 은퇴 보관본에 리그 요약이 없고 전체 커리어도 없으면 WAR는 `—`다. 현대 평균을 덮어쓰지 않는다. 통산은 자료가 온전한 경우만 완전한 값으로 표시하며, 누락이 있으면 카드에 ‘계산 가능한 시즌 합계’와 제외 시즌 수를 표시한다. 시즌별 표의 불완전한 통산 WAR는 `—`로 둔다. 완전한 커리어 JSON을 다시 불러와 은퇴 보관하면 해당 시즌 리그로 복원할 수 있다.

시즌 결과의 기존 스탯 창에 WAR를 추가한다. 1·2군 탭은 각 리그 기준으로 표시한다. 은퇴 화면과 보관 선수 상세에는 정규시즌 1군 통산 WAR 및 최고의 시즌 3개(연도·당시 팀·포지션·WAR·주요 기록)를 표시한다. 2군·아마추어 WAR를 프로 통산에 더하지 않는다.

숫자는 모두 소수점 첫째 자리다. TOP 3 순위는 표시한 한 자리 값으로 판정한다. 동률은 공동 순위, 안에서는 이른 연도 순이며 정확히 세 시즌까지만 보여준다. 통산은 반올림 전 원값을 합산한 뒤 반올림한다.

## 검증

고정 시드 3·17·41 × (2028/.85, 2030/1.0, 2033/1.15 득점 환경)의 **9개 리그·90개 팀 시즌**, 유격수·DH·포수·선발·중간계투·마무리 × 능력치 55·75·90의 **18개 선수 시즌**을 실행했다. `b74eccd`와 같은 9개 시즌의 선수 원기록 전체가 일치해 WAR 관측 추가가 경기 결과를 바꾸지 않았음을 확인했다. 시즌별 득점/승은 실제 관측 환경에 따라 8.22~12.99로 달라졌다. 타자 WAR 범위는 −1.88~8.12, 투수는 −1.55~4.83이었다.

팀 WAR + 대체 수준 승수(144경기에서 42.37승)와 실제 승수(무승부는 0.5승)의 평균 절대 편차는 **4.14승**, 최대 **22.04승**, 상관계수는 **0.837**이었다. 승수를 정확히 재현하도록 팀별 값을 강제 보정하지 않았다.

최대 편차는 시드 41·2028 저득점 환경의 팀4였다. 실제 91승, 모형 68.96승, 득실점 519:458의 피타고리안 기대값(지수 1.83)은 80.20승이다. 약 10.8승은 실제 승수와 득실점 기대값 사이 차이다. 또한 실제 RA9 3.12 대비 FIP 계열 RA9 3.61(예상 실점 529.6, 실제 458)이므로 FIP가 반영하지 않는 피안타·타구·수비·순서 효과가 약 71.6실점 있다. 나머지 차이에도 중립 수비와 선형 타격/구장 모델 한계가 포함된다. 접전 운용·수비를 완전히 분리했다고 보지 않는다.

능력치 75의 예시(2030·시드17): 유격수 4.60, DH 3.00, 포수 5.36, 선발 3.57, 중간계투 1.43, 마무리 1.12 WAR. 이들은 같은 원기록의 단순 포지션 교체 실험이 아니라 서로 다른 시즌 시뮬레이션이다. 능력치 90 DH가 75 DH보다 낮은 2.28인 사례도 관측했다. 능력치에 WAR를 직접 부여하지 않으므로 해당 시즌 실제 타격 결과·출장량 변동을 그대로 반영한다.

전체 `node --test tests/*.test.js` **195개 통과·실패 0개**. 마지막 WAR 관련 정리 후 해당 8개 회귀도 다시 통과했다. 독립 Chrome의 390px·1280px에서 포수·선발·중간계투·마무리 각각 시즌 스탯 WAR, 재로딩, 은퇴 TOP 3, 보관 상세 재열기와 값 일치·가로 넘침 없음·브라우저 오류 없음을 확인했다. `git diff --check` 통과.

회귀 검사는 타격/볼넷/장타/도루 성공·실패 반응, 수비 능력·실책만의 가짜 수비 가치 방지, 복수 포지션 실제 비중, 선발/불펜 이닝, 승패·세이브에 대한 불변성, 시즌 환경·구장·이적 비중, 기록 수정, 저장 복구·은퇴 스냅샷, 리그 미기록, TOP 3 동률과 통산 분리를 포함한다.

```bash
node --test tests/*.test.js
node scripts/war-audit.mjs --baseline=b74eccd > /tmp/war-audit.json
```

외부 기관의 WAR 값과의 수치 일치, 실제 KBO 대체 수준·포지션 득점·파크팩터 적합성은 검증하지 않았다. 기존 대형 결과물이나 사용자 원본 저장은 덮어쓰지 않았다.
